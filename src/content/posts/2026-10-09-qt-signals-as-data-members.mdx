A signal can be a callable data member, and Qt will not connect to it. GCC 16.2, with the Qt 6.10 headers on Compiler Explorer:

```text
error: no type named 'Object' in 'struct QtPrivate::FunctionPointer<std::function<void(int)> A::*>'
```

That is the first of three designs for signals that did not work, and the reason a signal in reflect-moc is declared as `rqt::signal<void(int)> valueChanged;`. This post covers the failures, the design that held, what it costs in bytes, and three alternatives I measured. It continues <PostLink slug="qt-metaobject-from-reflection">the previous post</PostLink>, where a reflected `QMetaObject` was accepted by stock Qt. The library is [published on GitHub](https://github.com/wrocpp/reflect-moc) (experimental: GCC 16.2, Qt 6.10.3, aarch64 Docker only).

## What moc writes for a signal

A signal is a member function that you declare and never define. moc defines it. The Qt wiki page on reflection and moc shows the generated body for `QWidget::windowTitleChanged` in Qt 6.10: one call, `QMetaObject::activate<void>(this, &staticMetaObject, 0, nullptr, _t1);`, with the signal's index and its arguments.

Reflection can list the signals. It cannot write that body. In P2996R13, `define_aggregate` takes descriptions of non-static data members (section 4.4.19), and the same section notes that the union support "allows implementing variant without having to further extend support in define_aggregate for member functions". The wiki page, last edited on 20 January 2026, puts it plainly: since signals are ordinary member functions, a definition cannot be injected, and token-sequence injection (P3294, "C++29 material at this point") would be needed. It also floats an escape close to the one this post takes, signals declared as something other than member functions (it guesses "a static data member"), and doubts that it is worth the break with Qt's history.

A signal that is not a function needs two things a function gets for free: it has to know which object it belongs to, and which of the object's signals it is.

## Three designs that did not work

**A callable data member.** The error above is the whole story. Qt reads the class of a signal from `QtPrivate::FunctionPointer<Func>::Object`, which exists for pointers to member functions. A `std::function` member has no such specialization. A `static constexpr auto` closure member fails the same way, with `FunctionPointer<const A::<lambda(int)>*>`. Both errors come from a compile-only run on Compiler Explorer (GCC 16.2, Qt 6.10.0 library). That session is quoted here and not embedded, because its output pane is red by design.

**A tag from `std::source_location`.** To tell members apart, give each a distinct type. A default template argument that records the declaration's line looks like it would. It does not: the default is evaluated once, where the template is declared, so every member gets the same type. GCC 16.2 also refuses the raw object, with `'std::source_location' is not a valid type for a template non-type parameter because it is not structural`; the version below uses `.line()`, which compiles and gives one type for all members.

**A tag from a closure.** `template <class Tag = decltype([] {})> struct sig` gives every member its own type, because every closure is a new type. The type has internal linkage, and in a header GCC says so:

```text
signal_header.h:4:8: warning: 'ByClosure' has a field 'sig_by_closure<> ByClosure::a' whose type has internal linkage [-Wsubobject-linkage]
```

The second link reproduces that warning on Compiler Explorer; a line marker makes GCC treat the class as header code, which is where the warning applies. In the project's first Qt-like ports built with this design, the same warning appeared 5, 5 and 42 times for mandelbrot, queuedcustomtype and birthdayparty, once per signal member per translation unit ([`examples/qt/RESULTS.md`](https://github.com/wrocpp/reflect-moc/blob/4fe8523bdf80342991df6d5f5f4774a5ee8c0cfd/examples/qt/RESULTS.md), build 1). The fourth example, sliders, did not build at all in that run, so it has no count. It also makes the member type different in every translation unit that includes the header, an ODR hazard, so silencing the warning would hide a real problem.

## A function that writes its own body

One form needs none of this. A signal can stay a member function with a one-line body:

```cpp
[[= rqt::signal_function]] void valueChanged(int v) { rqt::activate{this}(v); }
```

`rqt::activate` finds the signal from `std::meta::current_function()` in a default argument, which is GCC only. Qt sees an ordinary member function, so connect works unchanged. It adds no data member to the object, and it is the only form for an overloaded signal, since two data members cannot share a name. What it does not do is remove the boilerplate: the user writes the body that moc used to write, once per signal, with the right argument list. That is the work I wanted the library to take over, so this is the fallback and not the default.

## The data member that held

```cpp
class Sensor : public QObject {
  RQT_OBJECT
 signals:
  [[= rqt::names("level")]] rqt::signal<void(int)> levelChanged;
};
```

`RQT_OBJECT` declares a hidden first data member, the owner anchor. Its constructor takes its own address, subtracts its own offset (the compiler supplies it through `std::meta::offset_of`) and publishes the result as the owner. Each `rqt::signal` declared after it keeps that pointer, 8 bytes, and finds which signal it is by its own offset in a table of signal members that reflection builds. `rqt::signal<void(int), Owner>` is one type for every member of one signature, with external linkage, so a class in a header is the same type in every translation unit.

The Qt-free reduction below runs on Compiler Explorer. Three signals, two with the same signature, all told apart:

```text
non-static: emit Counter::valueChanged (offset 8)
non-static: emit Counter::alsoChanged (offset 16)
non-static: emit Counter::done (offset 24)
```

For Qt, one specialization teaches `connect` what a pointer to such a member is:

```cpp
namespace QtPrivate {
template <class Obj, class... A, std::meta::info Owner>
struct FunctionPointer<rqt::signal<void(A...), Owner> Obj::*> {
  using Object = Obj;
  using Arguments = List<A...>;
  using ReturnType = void;
  // ...
};
}
```

With that, pointer-to-member and lambda `connect`, `QMetaMethod::fromSignal` and `QSignalSpy` accept `&Sensor::levelChanged`. A signal used as the receiver of a connect needed one more change: Qt passes the receiver as a plain `QObject*` for anything that is not a pointer to member function (`qobjectdefs_impl.h:547`), and the `sliders` example from Qt failed with `invalid conversion from 'QObject*' to 'SlidersGroup*'` until the specialization took a `QObject*` and cast it. `QtPrivate` is Qt's internal namespace, so this specialization follows Qt 6.10.3 and can break in another release.

What the anchor design cost, from the project's [`docs/measurements.md`](https://github.com/wrocpp/reflect-moc/blob/4fe8523bdf80342991df6d5f5f4774a5ee8c0cfd/docs/measurements.md) (GCC 16.2.0, Qt 6.10.3, Linux aarch64 in Docker, on a Mac that was heavily loaded):

| check | result |
|---|---|
| header class in two translation units, `-Werror -Wall -Wextra`, no `-Wno-subobject-linkage` | compiles with 0 warnings, test passes |
| the same with `-flto -Wodr` | compiles with 0 warnings, test passes |
| `sizeof` of the benchmark class (3 signals, a `QObject`) | 24 bytes (closure tag, 1 byte per signal) to 48 bytes (anchor: 8 bytes per signal, 1 byte for the anchor, padding) |
| emit connected to one lambda, `-O2`, 5 000 000 emits | anchor 52.6 / 87.7 / 39.1 ns; closure tag 261.8 / 49.7 / 51.3 ns over three runs |

The emit numbers are the same within the noise of that machine: about 40 to 50 ns per emit, most of it inside Qt's own `QMetaObject::activate` and the functor call. I would not quote a ratio from them.

## Two more ways to get the size back

The 8 bytes per signal bothered me enough to try two ways to avoid them.

**A non-static member that takes no space.** Mark each signal `[[no_unique_address]]`, make its type unique per member, and a signal is empty. The runtime tests (property, QML, queued, string connect, `qobject_cast`) passed, and `capability_signal_to_signal_connect` failed (spike 08 in the project's [`spikes/SPIKES.md`](https://github.com/wrocpp/reflect-moc/blob/4fe8523bdf80342991df6d5f5f4774a5ee8c0cfd/spikes/SPIKES.md)). A direct check shows why. With two such signals `first` and `second`, `connect(&o, &W::second, ...)` followed by `first(7)` ran the `second` handler (`h2=7`), and `QMetaMethod::fromSignal(&W::second).methodIndex()` returned 4 where `indexOfSignal("second(int)")` returned 5. The cause is in Qt. For a pointer-to-member connect, Qt passes the raw bytes of the pointer to data member into the meta-object's `IndexOfMethod` call, and `QtMocHelpers::indexOfMethod` in `qtmochelpers.h` compares those bytes with each signal's pointer. Two empty members can sit at the same offset, so their pointers have equal bytes and the first match wins. The Qt-free demo shows the two ingredients: `ZeroSize offsets: first 0, second 0` and `raw bytes of &ZeroSize::first and &ZeroSize::second equal: yes`. Deducing `this` recovers the owner of a call, but `o.first(1)` and `o.second(1)` deduce the same object and the same call shape, so it cannot tell them apart. A member with a size has its own offset, which is why the anchor design keeps a pointer per signal.

**A static member, identified by its address.** `static inline rqt::static_signal<void(int)> levelChanged{};` takes no space in any object, because there is one per class. Measured by `capability_static_signal_size` (`sizeof(QObject)` is 16):

| class | `sizeof` |
|---|---|
| 1 non-static `rqt::signal`, `RQT_OBJECT` | 32 |
| 3 non-static `rqt::signal`, `RQT_OBJECT` | 48 |
| 3 `rqt::static_signal`, `RQT_OBJECT_STATIC` | 16 |
| 3 `rqt::static_signal`, `RQT_OBJECT` (the anchor stays) | 24 |
| 1 non-static + 2 static, `RQT_OBJECT` | 32 |

A non-static signal costs 8 bytes and the class 8 for the anchor. A static signal costs 0, and `RQT_OBJECT_STATIC` drops the anchor's 8. Stock `connect`, `fromSignal`, queued connections, QML and the differential test against moc all pass for static signals. Emit with no connection, 10 000 000 emits per run on the loaded Mac, three runs: 9.51 / 10.35 / 10.55 ns for the first non-static signal and 8.82 / 8.78 / 10.09 ns for the first static one. The project's own note says to read nothing into differences under about 2 ns.

The catch is the firing syntax. A static member is one object for the whole class, so it cannot know which instance emits it. The compat header redefines `emit` as `::rqt::emitter{this},` and a comma operator fires the pending call:

```cpp
void setLevel(int v) { emit levelChanged(v); }           // fires on this
levelChanged(v).from(other);                             // fires on another object
```

That works, and it has one silent failure. `emit other->levelChanged(v)`, where `other` is another instance of the same class, compiles and fires on `this`, because the static member discards `other`. Qt's own signals would fire on `other`. The library guards the other misuses at compile time (a bare `levelChanged(1);` is `-Werror=unused-result`, `emit` in a static member function is `'this' is unavailable for static member functions`, a const owner is refused) and the silent one with a lint, [`tools/rqt-lint-emit.py`](https://github.com/wrocpp/reflect-moc/blob/4fe8523bdf80342991df6d5f5f4774a5ee8c0cfd/tools/rqt-lint-emit.py), which flags the line. A lint is weaker than a compile error, and that is the price of the 8 bytes. Also, `static constexpr` does not work: Qt `reinterpret_cast`s the pointer through a non-const type, so the member must be `static inline` and non-const.

## Choosing a form

| form | bytes per signal | bytes per class | stock `connect` | how it is fired | known problem |
|---|---|---|---|---|---|
| `rqt::signal<void(int)> s;` (default) | 8 | 8 (the anchor) | yes | `s(v)` or `emit s(v)` | `RQT_OBJECT` must come first in the class |
| `static inline rqt::static_signal<void(int)> s{};` | 0 | 0 with `RQT_OBJECT_STATIC`, else 8 | yes | `emit s(v)` or `s(v).from(obj)` | `emit other->s(v)` on the same class fires on `this`, silently |
| `[[= rqt::signal_function]] void s(int v) { rqt::activate{this}(v); }` | no data member | none measured | yes | `s(v)` | the user writes the body; the only form for an overloaded signal |
| non-static, no size | 0 | none | no (the wrong signal fires) | none | two signals can be reached as one |

The last row is not shipped. I have not measured a class that uses only function-form signals, so the table makes no size claim for that row beyond "no data member".

## What this has not been tested on

- GCC 16.2 only. On Compiler Explorer's `clang_bb_p2996` on 6 October 2026, `offset_of` compiled, while `std::meta::current_class` and `current_function` are not declared in its `<meta>`. The closure and `source_location` results above are GCC 16.2 results.
- Qt 6.10.3, Linux aarch64 in Docker, offscreen platform plugin. Not x86_64, not other Qt versions, not clang or MSVC. Compiler Explorer has no Qt it can link, so the Qt connect errors were seen in a compile-only run and are quoted, not embedded; the Qt-free demo is the part that runs there.
- Sizes are `sizeof` results of the project's own tests. Timings come from one invocation of three runs on a heavily loaded Mac, and I read none of the emit differences as real.
- ThreadSanitizer: [`scripts/tsan-qt.sh`](https://github.com/wrocpp/reflect-moc/blob/4fe8523bdf80342991df6d5f5f4774a5ee8c0cfd/scripts/tsan-qt.sh) ran three threaded tests (`capability_static_signal_queued`, `capability_queued_across_qthread`, `capability_signal_to_signal_connect`) with 0 reports, and its control, a real race, gave 1 report. That needs `TSAN_OPTIONS=ignore_noninstrumented_modules=1`, because without it TSan reports the copy of queued arguments in every test as a race (Qt hands them over through a futex mutex it cannot see). `capability_custom_metatype_queued` reports 8 races even with the option, since it reads plain members after a `QSemaphore::acquire`, so it was left out. A ThreadSanitizer build of Qt would remove both limits and was not tried.
- The `emit` macro of the compat header is untested with `-DQT_NO_KEYWORDS`. A class template with a signal member fails to build, with either data-member form.
