# A vote is not the same as agreement

## Body
C++26 contracts are in the working draft, implemented in GCC 16.1, and demonstrable today. The August mailing contains a paper by the designer of C++ arguing they should come out anyway.

The objections that can be checked: several pieces are deferred to C++29, no shipping production codebase uses the feature, the standard libraries harden with their own macros instead, and the set of evaluation semantics was still growing during review.

But two numbers matter. The removal vote already happened and lost, 41 strongly against. And the related UB framework was approved with nobody strongly against.

So the argument is really about process: whether counting votes settles whether a foundational feature is finished.

Both cases, from the papers: https://wrocpp.github.io/posts/contracts-dispute/
